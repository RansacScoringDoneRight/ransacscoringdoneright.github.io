Working on the stack

This page is for people who change this package or the packages around it. It lists the VisualGeometryToolkitCore contracts the package implements, how the GPU grid evaluators and the SIMFIT++ port are organised, the vocabulary the package adds to the stack's, and how the repository is laid out. The Overview explains the same pieces from a user's point of view.

Contracts implemented

VisualGeometryToolkitCore owns the contracts. This package implements them for its own types and re-exports nothing VisualGeometryToolkitCore owns.

The scoring contract lives in VisualGeometryToolkitCore's robust/estimation.jl. StudentTUniformScoring implements scoring_workspace (its ScoringWorkspace), score! (the sort-and-sweep of Algorithm 1), inlier_count, consensus_order, scale_prior, outlier_halfwidth, check_workspace and with_width/width_axis (the axis is OutlierHalfwidth). Its inlier_threshold is the MAP crossover of the consensus set's ŝ² against the uniform outlier box. StudentTUniformScoring{Predictive} also implements is_predictive and scored_model. VisualGeometryToolkitCore derives the consensus scale (consensus_s2), the soft inlier weights and the Student-t posterior toolkit from these methods.

The pool-selection contract lives in VisualGeometryToolkitCore's robust/pool_selection.jl. Every grid family of this package declares the :rsdr staging through selection_staging and stage_selection, and implements select_on_grid! over its device kernels. The families are the marginal, the width-free loss-width families, LossSpec, ScaleMarginal and SimFitPP. VisualGeometryToolkitCore's best_pool_model(scoring, pair, R) serves any scorer at its width; this package adds the method for its width-free loss-width families.

Problems implement VisualGeometryToolkitCore's AbstractConstraintProblem: data_size, codimension, minimal_sample_size and constraint_with_jacobians. Predictive scoring also needs solver_covariance, declared by provides_solver_covariance. The RANSAC loop and the concrete problems are VisualGeometryToolkitEstimation's. The local-optimization strategies are VisualGeometryToolkitEstimation's and LocalOptimizationDoneRight's. A caller composes them, for example

find_essential(camera1, camera2, cs;               scoring = StudentTUniformScoring(EssentialProblem, a),               local_optimization = …)

RANSAC and MSAC at a threshold (RansacScoring, MsacScoring) are VisualGeometryToolkitCore's baseline scorers. This package adds their grid methods.

GPU scoring with KernelAbstractions

The files ig_sweep_ka.jl, loss_width_sweep_ka.jl and marg_sweep_ka.jl hold device kernels that run on the CPU and on CUDA. They score a pool that is staged once with stage_ig_shared_from_pairs(pairs, residuals; backend) from the light pool records (VisualGeometryToolkitCore's PoolPair) and their residual matrices. One verb, grid_evaluate, evaluates a grid and dispatches on the scoring:

  • grid_evaluate([S,] loss_width_scoring(:msac, dg), staged, loss_widths; aggregation) evaluates the loss-width baselines. These are RANSAC, MSAC, GaU (MLESAC) and MAGSAC++, plus the Welsch, smooth-TLS and Geman–McClure losses. Each scores through one per-residual scalar, residual_quality(scoring, d², loss_width). The aggregation is Exact (every residual, the reference) or LogBinned (bins_per_decade = 200, the fast cross-validation path and the default).
  • grid_evaluate(StudentTUniformScoring(problem_type, h; prior), staged, outlier_halfwidths) is the IG/Jeffreys marginal sweep. The grid replaces the scoring's own h.
  • grid_evaluate([S,] loss_spec(shape, prior; Δ, …), staged, outlier_halfwidths; model_dof, dg) is the Track-B redescending-loss mixture marginal.
  • grid_evaluate([S,] WelschMarginal(; prior_loss_width, outlier_halfwidth), staged, prior_loss_widths) evaluates the full-data scale marginals. The grid replaces the prior centre.

VisualGeometryToolkitCore's width_axis(scoring) names the axis a scoring's grid is native on (OutlierHalfwidth or LossWidth), and this package states it for its grid families. VisualGeometryToolkitCore's to_native(axis, scale_multiple, scale; d_g) maps a scale multiple onto that axis, and native_map(axis; d_g) is the same map curried.

The kernels run on CPU() or CUDA.CUDABackend(). The Float64 device path is bit-identical to the CPU reference; test/gate_marg_mix_ka.jl checks this and also runs on CUDA with --cuda. Each grid evaluator frees its function-local device buffers eagerly through GPUArrays.unsafe_free! instead of waiting for Julia's garbage collector.

The SIMFIT++ port

src/simfitpp.jl ports Edstedt's SIMFIT++ (CVPRW 2025, Parskatt/simfitpp) step for step. The reference calls the loss width its threshold.

  • unbiased_median_variance is the reference's UnbiasedMed. It takes the median of the squared residuals below the current loss width and removes the bias of the truncation with the χ² fixed-point quantile iteration. It returns σ², hence the name.
  • simfitpp_loss_width is SIMFITPP.__call__. It splits the data at random into a train and a validation part and estimates the geometry on the train part at the current loss width. The held-out residuals give a variance and from it a loss width sqrt(ppf(alpha)·σ²). The loop then applies the bounds, keeps a running mean and stops on ftol or a repeat. A final bounds check and a cross-pair filter in log space follow.
  • The geometry estimator is a pair of callbacks, so the loop runs on a full RANSAC (as in the reference) or on a hypothesis pool. simfitpp_select(pair, initial_loss_width_px) uses the MSAC-best pool hypothesis on the train part as the estimator. It returns the MSAC-best hypothesis over all points at the estimated loss width.
  • SimFitPP holds the reference defaults: alpha = 0.99, max_iter = 4, ftol = 0.01, train_fraction = 0.5, min_loss_width = 0.25, max_loss_width = 8 and dg = 1.

The reference's bounds, 0.25 and 8, are pixel constants. A pool stores its data in NormalizedImageFrame (image centre, half diagonal), and no single scalar relates the two frames point by point. pixel_residuals(pair) is the image-plane Sampson residual of the pool's models in pixels. It is computed from the light record and never reads the stored residual matrix, so it does not depend on that matrix's residual kind (tangent Sampson for E pools). The pair method of simfitpp_select runs on it, so initial_loss_width_px, the bounds and the returned loss width are all in pixels. To work in the pool frame's unit instead, call the matrix method on the pair's residual matrix with bounds in that unit. residual_unit_scale(pair), the mean pool-frame-per-pixel scale, is a convention for soft quantities only, such as an initial guess taken from a grid in the pool frame's unit.

Scoring and tuning vocabulary

This package holds the vocabulary and the per-pair machinery. That is the per-pair selection over a pool record and its residual matrix (best_pool_model for the width-free loss-width families, pool_model_score, precompute_pair) and the KernelAbstractions grids above. A scoring at its width is its own pool-selection handle.

Other layers live elsewhere. The prior-spec layer that fits IGPrior from validation data (PriorSpec, fit_prior) is VisualGeometryToolkitEval's Tuning. The pool record, PoolPair, and its accessors (num_points, num_models, pool_imc, pool_normalization and others) belong to VisualGeometryToolkitCore's Pools module. Pool IO belongs to VisualGeometryToolkitEval.

The layer is problem-agnostic. The concrete problem types (HomographyProblem, FundMatProblem, EssentialProblem) stay in the consumer. A scorer that needs one takes it as a leading problem_type argument, as in best_pool_model(StudentTUniformScoring(problem_type, outlier_halfwidth), pair, R).

Names of quantities

VisualGeometryToolkitCore's robust layer is authoritative for the loss words. The shape math is ρ, ψ and weight. A scale_multiple is the dimensionless multiple of the scale at which a width sits, s2 is the noise variance, loss_width is a loss's scale parameter and sq_loss_width is its square (scale_multiple² · s2 for a deployed loss). VisualGeometryToolkitCore writes the squared residual as s in ρ(shape, s, sq_loss_width). This package writes it sq_r or sq_residuals, never s.

On top of that, this package names the following quantities.

namequantity
outlier_halfwidththe half-width of the uniform outlier component
decision_thresholdthe residual at which the MAP rule flips
decision_threshold / decision_widththe one map between the two (VisualGeometryToolkitCore's generic, with the mixture's method), so a grid of outlier half-widths is never called a grid of thresholds
operating_scale_multiplethe scale multiple at which a protocol converts (loss_width = operating_scale_multiple · ŝ)
ŝ, s_hat_sqthe scale estimate and its square
d_g / dgthe constraint codimension
inlier_prior / inlier_posteriorthe scalar mixing proportion π and the per-point P(inlier | r)

A name that contains scale returns a linear scale (residual_unit_scale). A name for a squared quantity says so (unbiased_median_variance, s_hat_sq, sq_loss_width). The one exception is fit_scale, which is named for the fit contract; its docstring states first that it returns the square.

Repository layout

src/                   the package: the sort-and-sweep marginal scorer, the grid
                       evaluators (KernelAbstractions), the baseline families, SIMFIT++
test/                  the package's tests (ReTestItems)
docs/                  the documentation site (Documenter)
neurips2026/           the research project (DrWatson layout, devs this package):
  Project.toml         every dependency the drivers need (`@quickactivate "NeurIPS2026"`)
  paper/               the manuscript (arXiv version); generated figures in paper/figures/
  scripts/             the figure drivers (stage-idempotent), the data fetch,
                       studies/ (the scoring studies) and slurm/ (their launchers)
  configs/             configs of record (figures, prose-number check, pools, data catalog)
  src/                 the shared prelude: the ported panel renderers, verify/deploy
  test/                the project's tests (`julia --project=. test/runtests.jl`)
  data/                exp_raw / exp_pro bindings (per machine, not tracked)
  notes/               write-ups of the scoring studies
  REPRODUCE.md         the figure → generator → config → data index, and what is not ported

The package, its tests, its docs and the research project are one Pkg workspace. They resolve together into one Manifest.toml at the repository root, which is not committed.

The split follows one rule. What a second paper or a user's RANSAC reuses (the scorers, their grids, the per-pair selection) belongs in the package. Drivers, figures, configs of record and stored results belong in neurips2026/. The package never depends on the project.

Development

The repository ships git hooks in .githooks/ that keep the local Manifest.toml resolvable. After a pull, checkout or rebase that changes the Project.toml of any workspace member, they re-resolve the workspace. They only resolve; precompilation waits for the next using. The hooks are opt-in, once per clone:

git config core.hooksPath .githooks

The package's tests use ReTestItems, one item per test/*_tests.jl file. Pkg.test(; test_args = ["simfitpp"]) runs the items whose name matches. The research project's suite is separate: cd neurips2026 && julia --project=. test/runtests.jl.
